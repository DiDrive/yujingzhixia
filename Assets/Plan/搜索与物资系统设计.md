# 搜索与物资系统设计

## 目标

建立可复用的局内搜刮闭环：

```text
发现目标 → 按住搜索 → 打开容器 → 逐件揭示 → 转移到背包 → 保留容器状态
```

## 模块边界

### `PlayerInteractor2D`

- 扫描附近 `IWorldInteractable`。
- 选择最近且有效的目标。
- 处理按住交互键的进度。
- 不负责生成掉落，不保存容器状态。

### `SearchableLootContainer`

- 管理单个世界容器的首次搜索和 UI 开关。
- 请求 `LootTableDatabase` 生成首次掉落。
- 管理逐物品揭示队列。
- 导出并恢复自己的状态快照。

### `GridInventoryService`

- 管理容器、物品实例、格子占用与跨容器移动。
- 提供按指定格子恢复物品并返回新实例 ID 的接口。
- 不判断“是否搜索过”。

### `SearchableLootRuntimeStateStore`

- 使用 `persistentId` 保存会话级容器快照。
- 在场景重载时恢复状态，阻止重复抽取。
- 不创建 GameObject，不依赖 UI。
- 后续可由正式存档服务读取和写入相同快照。

### `ZombieCorpseLootController`

- 僵尸存活时关闭尸体搜索点，死亡后才注册为世界交互物。
- 死亡时把尸体唯一 ID、显示名称、所在楼层、掉落表和网格尺寸传给 `SearchableLootContainer`。
- 尸体未搜索或仍有物品时阻止原有自动淡出；搜空并关闭 UI 后才恢复淡出。
- 所有尸体共用编辑器中预先制作的 `InventoryUI_corpse_shared`，运行时不创建整套 UI。

## 状态快照

容器快照包含：

- `persistentId`
- `populated`
- `searched`
- 剩余物品：
  - `itemId`
  - `stackCount`
  - `rotation`
  - `row`
  - `column`
  - `revealed`

不保存正在搜索某件物品的瞬时进度。场景切换时，未完成的当前物品从零重新搜索，避免保存帧级临时状态。

## 生命周期

1. 容器 `Awake` 时注册运行时网格容器。
2. 按 `persistentId` 查询会话级快照。
3. 有快照：恢复剩余物品、位置及揭示状态。
4. 无快照：保持未生成状态，首次成功搜索时抽取掉落。
5. 生成物资、揭示物品、关闭 UI、禁用对象时更新快照。
6. 新一局开始时，由局流程调用状态仓库清空接口。

### 尸体容器生命周期

1. 僵尸 Prefab 中预先放置默认关闭的 `CorpseSearchPoint`。
2. 僵尸死亡后关闭活体碰撞器，并激活尸体搜索点。
3. 尸体记录死亡时楼层并生成本局唯一 `corpse_GUID`，避免多具尸体串用库存。
4. 玩家首次搜索时才按尸体掉落表生成物资，然后沿用普通容器的逐件揭示流程。
5. 尸体被取空且共享 UI 关闭后，关闭搜索点并开始延迟淡出。

## 配置所有权

- Player 已挂载 `PlayerInteractor2D`：以 Player Inspector 为准。
- Player 未挂载、由 Bootstrap 临时创建：使用 Bootstrap 默认值。
- 禁止同一运行对象由两个 Inspector 字段持续互相覆盖。

## 验收标准

- Player 上的交互距离不会在启动时被 Bootstrap 覆盖。
- 同一 `persistentId` 在同一局内重新加载场景不会重新抽取掉落。
- 已取走物品不会在重载后重新出现。
- 剩余物品保持数量、旋转和格子位置。
- 已揭示物品重载后保持正常显示。
- 新放入世界容器的玩家物品默认视为已知，不显示搜索蒙版。
