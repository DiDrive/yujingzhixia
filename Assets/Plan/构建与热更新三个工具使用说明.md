# 构建与热更新三个工具使用说明

## 文档信息

| 字段 | 内容 |
|---|---|
| 适用项目 | 余烬之下 |
| 适用平台 | Windows 64 位 |
| 资源系统 | YooAsset `DefaultPackage` |
| 代码热更新 | HybridCLR `HotUpdate.dll` |
| 最后更新 | 2026-11-03 |

## 一句话结论

项目目前有三个工具，但不是每次三个都要执行：

| 工具 | 一句话作用 | 最常见的使用时机 |
|---|---|---|
| 基础客户端构建 | 生成一个新的 Windows 客户端 EXE | 首次出包，或修改了不能热更新的主工程代码 |
| 远程更新构建 | 生成旧客户端可以下载的热更新资源 | 修改资源、JSON 或 `Assets/HotUpdate` 代码 |
| 发布到本机 CDN | 把已经构建好的更新安全放到 HTTP 服务器目录 | 基础构建或远程更新构建成功之后 |

最常用的两条流程：

```text
发布新客户端：基础客户端构建 → 发布到本机 CDN → 分发并启动新客户端

日常热更新：远程更新构建 → 发布到本机 CDN → 启动旧客户端测试更新
```

不要把三个工具固定理解成必须连续执行的三个步骤。

---

## 一、基础客户端构建

### 菜单位置

```text
Tools → 余烬之下 → 构建与发布 → 基础客户端构建
```

### 它解决什么问题

它负责生成玩家可以直接运行的 Windows 客户端：

```text
PlayerBuilds/PC/<客户端基线>/EmbersBelow.exe
```

它还会为这个新客户端生成同版本的初始 CDN 待发布资源：

```text
ReleaseStaging/PC/<客户端基线>/<资源版本>/
```

新客户端使用 `HostPlayMode`，启动时仍然会询问 CDN 当前版本。因此基础构建完成后，还要使用“发布到本机 CDN”，把配套的初始版本发布出去。

### 它自动做什么

1. 执行 HybridCLR `Generate/All`。
2. 校验 HybridCLR 生成结果。
3. 将最新 `HotUpdate.dll` 复制为 `Assets/AB/HotDll/HotUpdate.dll.bytes`。
4. 使用 YooAsset `ClearAndCopyAll` 构建内置资源到 `StreamingAssets`。
5. 只使用 `BootScene` 构建 Windows 64 位 IL2CPP Player。
6. 生成同一资源版本的 `ReleaseStaging` 初始 CDN 待发布目录。

### 什么时候必须使用

- 第一次制作可运行的正式客户端。
- 修改了 `Assets/Scripts` 下的普通 AOT 代码。
- 修改了启动更新界面或启动流程。
- 修改了 `BootScene` 中的对象、组件或 CDN 地址。
- 修改了 HybridCLR 桥接层，例如 `HotUpdateLootBridge`、`HotUpdateSurvivalBridge`。
- 修改了 Player Settings、原生插件、第三方 SDK 或 IL2CPP 相关设置。
- 准备建立一个新的客户端基线，例如从 `v1.0` 升级到 `v1.1`。

### 什么时候不用

- 只修改 `item_definitions.json`、`loot_tables.json`、`survival_rules.json`。
- 只修改 YooAsset 管理的图片、音效、Prefab 或业务场景。
- 只修改 `Assets/HotUpdate` 中的热更新代码。

这些情况使用“远程更新构建”即可。

### 窗口参数怎么填

#### 客户端基线

示例：

```text
v1.0
```

它决定：

```text
PlayerBuilds/PC/v1.0/
ReleaseStaging/PC/v1.0/<资源版本>/
CDN/PC/v1.0/
```

它必须和 `BootScene` 中以下地址的最后一级目录一致：

```text
defaultHostServer
fallbackHostServer
```

当前项目地址使用的是：

```text
http://127.0.0.1/CDN/PC/v1.0
```

因此当前应填写 `v1.0`。不能只在构建窗口里改成 `v1.1`，却不修改 BootScene 的 CDN 地址。

#### 内置资源版本

示例：

```text
20261103-001
```

每次构建都必须使用一个从未使用过的新版本号。建议直接采用工具自动给出的版本号。

已经发布过的资源版本不能覆盖，因为旧客户端或 CDN 缓存可能仍在引用它。

#### Development Player

- 日常调试、需要更完整日志时可以勾选。
- 准备发布或测试正式性能时不要勾选。

### 构建后的下一步

```text
基础客户端构建成功
→ 打开“发布到本机 CDN”
→ 发布刚生成的相同资源版本
→ 运行 PlayerBuilds/PC/v1.0/EmbersBelow.exe
```

这次不需要再执行“远程更新构建”。基础工具已经生成了同版本的初始 `ReleaseStaging`。

## 二、远程更新构建

### 菜单位置

```text
Tools → 余烬之下 → 构建与发布 → 远程更新构建
```

### 它解决什么问题

它不会生成新的 EXE，而是生成旧客户端启动时可以检查、确认并下载的资源更新。

输出目录：

```text
ReleaseStaging/PC/<玩家大版本目录>/<资源版本>/
```

目录中主要包括：

```text
*.bundle
DefaultPackage_<资源版本>.bytes
DefaultPackage_<资源版本>.hash
DefaultPackage.version
release-info.json
UPLOAD_ORDER.txt
```

### 什么时候使用

- 修改 `Assets/GameRes` 中的 JSON 配置。
- 修改 YooAsset 管理的图片、音效、Prefab、材质或场景。
- 修改 `Assets/HotUpdate` 中的热更新代码。
- 希望已经分发出去的旧客户端获得新内容。

### 窗口参数怎么填

#### 资源版本号

必须是从未使用过的新版本，例如：

```text
20261103-002
```

不能覆盖 `20261103-001`。

#### 玩家大版本目录

正常日常热更新继续填写：

```text
v1.0
```

日常小更新不需要从 `v1.0` 改成 `v1.1`。只有发布新的客户端基线并同步修改 BootScene CDN 地址时，才升级这个目录。

#### 先编译并复制 HybridCLR HotUpdate.dll

按修改内容决定：

| 本次修改内容 | 是否勾选 |
|---|---|
| 只修改 JSON、图片、音效、Prefab 或场景 | 可以取消勾选 |
| 修改了 `Assets/HotUpdate` 中的代码 | 必须勾选 |
| 不确定本次是否动过热更新代码 | 建议勾选 |

勾选后只会编译最新 `HotUpdate.dll`，不会执行完整的 HybridCLR `Generate/All`。

完整 `Generate/All` 属于基础客户端构建流程，不是日常热更新的必要步骤。

### 它不会做什么

- 不构建 Windows EXE。
- 不执行 `ClearAndCopyAll`。
- 不自动修改线上 CDN。
- 不会让 `Assets/Scripts` 中的普通 AOT 代码在旧客户端里生效。

### 构建后的下一步

```text
远程更新构建成功
→ 检查 Console 无错误
→ 打开“发布到本机 CDN”
→ 发布刚生成的 ReleaseStaging
→ 启动旧客户端验证更新大小、确认按钮和实际效果
```

## 三、发布到本机 CDN

### 菜单位置

```text
Tools → 余烬之下 → 构建与发布 → 发布到本机 CDN
```

### 它解决什么问题

前两个工具只负责“构建文件”，不会修改 CDN。

这个工具负责把 `ReleaseStaging` 中已经构建完成的文件安全复制到本机 IIS、Nginx、Apache 或其他 HTTP 服务器映射目录。

它既不编译代码，也不构建 Bundle 或 EXE。

### 它从哪里取文件

```text
ReleaseStaging/PC/<客户端基线>/<资源版本>/
```

窗口默认会尝试选择对应基线下最新的有效待发布目录。

### 窗口参数怎么填

#### 待发布版本目录

选择刚才由“基础客户端构建”或“远程更新构建”生成的具体版本目录，例如：

```text
D:/unity_project/余烬之下/ReleaseStaging/PC/v1.0/20261103-002
```

不要只选择 `ReleaseStaging` 或 `v1.0` 上级目录。

#### CDN 物理根目录

这里选择 URL 中 `/CDN` 对应的本地文件夹。

例如客户端访问：

```text
http://127.0.0.1/CDN/PC/v1.0
```

如果服务器把 `D:/GameCDN` 映射成 `/CDN`，这里应选择：

```text
D:/GameCDN
```

不要选择：

```text
D:/GameCDN/PC/v1.0
```

工具会自动在物理根目录下拼接 `PC/v1.0`。

#### CDN HTTP 根地址

本机测试通常填写：

```text
http://127.0.0.1/CDN
```

#### 玩家大版本目录

当前填写：

```text
v1.0
```

它必须和待发布目录及客户端 CDN 地址一致。

#### 通过 HTTP 校验所有发布文件

建议保持勾选。

启用后，工具会在正式切换版本前，通过 HTTP 检查 Bundle 和 Manifest 是否真的能访问，而不是只确认文件已经复制到磁盘。

### 为什么发布顺序很重要

工具会自动按照以下顺序发布：

1. 先发布所有 Bundle。
2. 再发布 Manifest 和 Hash。
3. 通过 HTTP 校验资源是否可访问。
4. 最后发布 `DefaultPackage.version`。

`DefaultPackage.version` 相当于“正式启用新版本”的开关。

如果先发布 version，客户端可能发现新版本，但对应 Bundle 还没上传完成，从而出现下载失败。不要手动打乱这个顺序。

### 发布后的下一步

- 初始基线发布：运行刚构建的新客户端。
- 日常热更新发布：运行未更新过的旧客户端。
- 确认显示正确的更新文件数量和大小。
- 点击确认下载，验证进度、进入游戏和修改效果。

## 四、我改了文件，应该用哪个工具

| 修改位置或内容 | 基础客户端构建 | 远程更新构建 | 发布到本机 CDN |
|---|---:|---:|---:|
| `Assets/GameRes/Config/*.json` | 不用 | 使用 | 使用 |
| YooAsset 管理的图片、音效、Prefab、材质 | 不用 | 使用 | 使用 |
| YooAsset 管理的 Raid/Shelter 场景 | 不用 | 使用 | 使用 |
| `Assets/HotUpdate/*.cs` | 不用 | 使用并勾选编译 DLL | 使用 |
| `Assets/Scripts/*.cs` 普通代码 | 使用 | 不需要为同一初始版本再执行 | 使用 |
| `BootScene`、启动 UI、更新逻辑 | 使用 | 不需要为同一初始版本再执行 | 使用 |
| Player Settings、插件、SDK、IL2CPP 设置 | 使用 | 通常不用 | 使用 |
| 已有 `ReleaseStaging`，只是重新尝试发布 | 不用 | 不用 | 使用 |

### 判断口诀

```text
改 GameRes：远程构建 + CDN 发布

改 HotUpdate：远程构建（勾选 DLL）+ CDN 发布

改 Scripts 或启动层：基础客户端构建 + CDN 发布 + 分发新 EXE
```

## 五、三个“版本”不要混淆

### 客户端基线

示例：

```text
v1.0
```

作用：划分一代客户端使用的 CDN 目录。日常热更新通常保持不变。

### YooAsset 资源版本

示例：

```text
20261103-001
20261103-002
```

作用：表示每一次资源构建结果。每次构建必须使用新版本号。

### Unity Player 版本

示例：

```text
0.1
```

来源：`PlayerSettings.bundleVersion`。

作用：表示应用自身版本，主要用于客户端版本展示和发行管理。它不是 YooAsset 资源版本，也不是 CDN 文件夹名称。

## 六、完整使用示例

### 示例 A：第一次发布 `v1.0` 客户端

1. 确认 BootScene CDN 地址为 `http://127.0.0.1/CDN/PC/v1.0`。
2. 打开“基础客户端构建”。
3. 客户端基线填写 `v1.0`。
4. 内置资源版本使用建议值，例如 `20261103-001`。
5. 正式测试不勾选 Development Player。
6. 点击开始构建。
7. 构建成功后打开“发布到本机 CDN”。
8. 发布 `ReleaseStaging/PC/v1.0/20261103-001`。
9. 运行 `PlayerBuilds/PC/v1.0/EmbersBelow.exe`。
10. 此时客户端内置版本和 CDN 版本相同，正常情况下不需要下载资源。

### 示例 B：只修改 `survival_rules.json`

1. 修改并保存 JSON。
2. 打开“远程更新构建”。
3. 使用新资源版本，例如 `20261103-002`。
4. 玩家大版本目录继续使用 `v1.0`。
5. 可以取消“编译 HotUpdate.dll”。
6. 构建成功后打开“发布到本机 CDN”。
7. 发布 `20261103-002`。
8. 启动原来的 `v1.0` 客户端。
9. 确认更新大小，点击确认下载并验证新生存数值。

### 示例 C：修改 `SurvivalRuleService.cs`

文件位于：

```text
Assets/HotUpdate/Survival/SurvivalRuleService.cs
```

操作：

1. 打开“远程更新构建”。
2. 使用新资源版本号。
3. 勾选“先编译并复制 HybridCLR HotUpdate.dll”。
4. 构建后发布到 CDN。
5. 启动旧客户端验证日志中的 `BusinessVersion`、`ApiVersion` 和 `SelfCheck=Passed`。

### 示例 D：修改 `GameContentService.cs`

文件位于：

```text
Assets/Scripts/Core/Content/GameContentService.cs
```

它属于 AOT 主工程代码，旧客户端无法通过 `HotUpdate.dll` 替换。

操作：

1. 使用“基础客户端构建”。
2. 发布工具生成的同版本初始 CDN 资源。
3. 分发新的 EXE。

只执行“远程更新构建”不会让旧客户端中的 `GameContentService` 发生变化。

## 七、常见问题

### 新的启动界面为什么没有出现在旧客户端

启动界面和 `BootUpdateUI.cs` 属于客户端启动层。修改后需要重新构建并分发基础客户端，不能只上传热更新资源。

### 编辑器里有效，EXE 中无效

依次检查：

1. 修改的文件属于 `Assets/HotUpdate`、`Assets/GameRes`，还是 `Assets/Scripts`。
2. 是否使用了正确的构建工具。
3. 是否使用了全新的资源版本号。
4. 是否把正确的 `ReleaseStaging` 发布到了 CDN。
5. CDN 的 `DefaultPackage.version` 是否已经指向新版本。
6. 客户端 CDN 地址和玩家大版本目录是否一致。

### 为什么不能重复使用同一个资源版本号

Bundle、Manifest 和 Hash 应视为不可变文件。覆盖同名文件可能导致 CDN 缓存、客户端缓存和 Manifest 内容互相不一致。

### 为什么不能每次都把 `v1.0` 改成 `v1.1`

`v1.0` 是客户端基线，不是每次热更新的版本号。日常更新只增加 YooAsset 资源版本。只有确实发布新一代客户端，并同步修改 BootScene CDN 地址时，才升级基线目录。

### 基础客户端构建后还要执行远程更新构建吗

为相同的初始资源版本不需要。基础客户端工具已经同时生成了初始 `ReleaseStaging`。

基础构建后直接执行“发布到本机 CDN”即可。

### 发布工具会不会构建资源

不会。它只负责安全复制和 HTTP 校验。没有有效 `ReleaseStaging` 时，不能只靠发布工具产生更新。

## 八、发布前检查清单

### 新客户端发布

- [ ] 当前平台是 `StandaloneWindows64`。
- [ ] Standalone 使用 IL2CPP。
- [ ] Build Settings 只启用 `BootScene`。
- [ ] BootScene CDN 地址和客户端基线一致。
- [ ] 使用了全新的 YooAsset 资源版本。
- [ ] 基础客户端构建成功且 Console 无错误。
- [ ] 初始 `ReleaseStaging` 已发布到正确 CDN 目录。
- [ ] 新客户端可以获取版本、进入游戏并加载业务场景。

### 日常热更新发布

- [ ] 已判断本次修改是否属于可热更新范围。
- [ ] 修改 `Assets/HotUpdate` 时已勾选编译 DLL。
- [ ] 使用了全新的资源版本号。
- [ ] 远程更新构建成功且 Console 无错误。
- [ ] CDN 发布时保持 HTTP 校验开启。
- [ ] 使用旧客户端测试了更新确认、下载进度和实际效果。
- [ ] `DefaultPackage.version` 最后发布。
