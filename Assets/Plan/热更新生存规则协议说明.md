# 热更新生存规则协议说明

本文记录 `SurvivalSystem`、`HotUpdateSurvivalBridge` 与 `SurvivalRuleService` 之间的调用关系和数组字段，防止后续维护时忘记下标含义。

## 1. 为什么使用数组

`SurvivalSystem` 属于基础客户端 AOT 代码，`SurvivalRuleService` 位于运行时加载的 `HotUpdate.dll`。基础客户端不能直接引用尚未加载的热更新类型，因此由 `HotUpdateSurvivalBridge` 按固定类型名和方法签名反射查找热更新方法。

生存衰减每帧执行。如果每帧把状态序列化成 JSON，会产生大量字符串和垃圾回收压力。因此高频 `Tick` 使用两个可复用的 `float[]`：

- `state`：当前状态和计算结果，热更新方法原地修改。
- `settings`：本帧时间、衰减速度和阈值，只读。平衡数值来自 YooAsset 的 `Assets/GameRes/Config/survival_rules.json`。

消耗品效果只在玩家使用物品时发生，频率很低，因此效果列表继续使用可读性更好的 JSON。

## 2. state 字段

| 下标 | 名称 | 方向 | 含义 |
|---:|---|---|---|
| 0 | Hunger | 输入/输出 | 当前饥饿值 |
| 1 | Thirst | 输入/输出 | 当前口渴值 |
| 2 | Fatigue | 输入/输出 | 当前精力值 |
| 3 | Hp | 输入/输出 | 当前生命值 |
| 4 | Infected | 输入/输出 | 感染状态，1 为 true，0 为 false |
| 5 | MaxHunger | 输入 | 饥饿值上限 |
| 6 | MaxThirst | 输入 | 口渴值上限 |
| 7 | MaxFatigue | 输入 | 精力值上限 |
| 8 | MaxHp | 输入 | 生命值上限 |
| 9 | MoveSpeedMultiplier | 输出 | 移动速度倍率 |
| 10 | DamageMultiplier | 输出 | 伤害倍率 |
| 11 | StaminaMultiplier | 输出 | 耐力倍率 |
| 12 | CanUseChargeAttack | 输出 | 能否蓄力攻击，1 为 true，0 为 false |

## 3. settings 字段

| 下标 | 名称 | 含义 |
|---:|---|---|
| 0 | DeltaTime | 本帧秒数 |
| 1 | AdvanceSurvival | 当前流程是否允许衰减，1 为允许，0 为暂停 |
| 2 | HungerDecay | 每分钟饥饿衰减量 |
| 3 | ThirstDecay | 每分钟口渴衰减量 |
| 4 | FatigueDecay | 每分钟精力衰减量 |
| 5 | WarningThreshold | 警告阈值，触发移动、伤害、耐力减益 |
| 6 | CriticalThreshold | 危险阈值，触发扣血或禁用蓄力攻击 |
| 7 | HungryHpLoss | 严重饥饿时每分钟生命损失 |
| 8 | ThirstyHpLoss | 严重缺水时每分钟生命损失 |
| 9 | InfectedHpLoss | 感染时每分钟生命损失 |

## 4. 兼容规则

1. 已发布基础客户端中的数组下标不会随新 DLL 改变。
2. 不得交换、删除或重新解释已有位置。
3. 需要新增字段时只能追加到数组末尾，并先考虑旧客户端数组长度不足时的兼容策略。
4. 修改 `Tick(float[], float[])`、`HasUsefulEffect(float[], string)` 或 `ApplyEffects(float[], string)` 的签名属于协议破坏，需要提高 `ApiVersion` 并重新发布基础客户端。
5. 只修改公式、倍率、效果规则或 `ImplementationVersion`，且保持上述协议不变时，可以只发布新的 `HotUpdate.dll`。
6. 热更新服务缺失或调用失败时，AOT 层会停用本次进程的热更新生存桥接，并回退到 `SurvivalSystem` 和 `ConsumableItemUseService` 中的内置规则。
